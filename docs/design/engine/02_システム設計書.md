# 02_システム設計書: Alchemy Incremental

## 0. 用語定義
| 用語 | 意味 | 補足 |
| :--- | :--- | :--- |
| **データ駆動** | 変更を「データ(JSON)の書き換え」だけで完結させる設計。 | 300個のレシピ管理に必須。 |
| **i18n** | 多言語対応の仕組み。 | 表示文字列を外部化して管理する。 |
| **GUIモジュール** | 画面表示・ユーザー入力を担当するモジュール群。 | ロジック層とは完全に分離する。 |
| **放置ロジック** | 離脱中の生産を計算する軽量計算エンジン。 | 秒間生産量 × 時間 × 係数で算出。 |
| **数値フォーマッタ** | 数値を「1.0M」「1.0e6」などの人間が読める形式に変換する機能。 | インフレ対策の必須機能。 |

## 1. 全体アーキテクチャ
データ駆動型設計を採用し、ロジック・データ・UIを完全に分離する。
- **データ層 (`recipe-db.json`)**: 静的な素材・レシピ・触媒情報を保持。
- **i18n層 (`locales/*.json`)**: 言語ごとの表示文字列を保持。
- **ロジック層 (`src/logic/`)**: 計算ロジック、ゲーム状態管理。
- **GUIモジュール (`src/gui/`)**: 描画、入力ハンドリング、エフェクトの可視化。

## 2. データ構造定義 (`recipe-db.json`)
全データは以下のスキーマに従う。

```json
{
  "materials": {
    "MAT_ID": { "nameKey": "string", "baseValue": "number", "tier": "number" }
  },
  "recipes": {
    "REC_ID": {
      "output": "MAT_ID",
      "inputs": { "MAT_ID": "number" },
      "baseTime": "number",
      "baseRate": "number",
      "effectIds": ["string"]
    }
  },
  "catalysts": {
    "CAT_ID": { "targetMaterial": "MAT_ID", "costGold": "number" }
  }
}
```

- **数値計算モデル**
  - **錬金成功判定**: `SuccessRate = BaseRate + (AP * 0.01) + (ML * 0.05)`
  - **価値計算**: `Value = baseValue * (1 + (エレメンタル恩恵)) * (1 + (品質ボーナス))`
  - **再創世 (結晶獲得量)**:
    - **基本条件**: 周回中に獲得した素材の総価値（TotalMaterialValue）に比例する。
    - **計算式**: `Crystals = floor(TotalMaterialValue * 0.01)`
  - **数値表示**: `Format(value) -> "1.00K", "1.00M", "1.00e6"`

## 4. プロの設計指針 (インクリメンタルゲームの鉄則)
- **Offline Progress**: 離脱中の報酬は、厳密なシミュレーションではなく「秒間生産量 × 時間 × 補正」の軽量計算で算出する。
- **Save/Load**: データバージョンを持たせ、過去データとの互換性を保つマイグレーション機能を初期から実装する。
- **Atomic Save**: 保存時は一時ファイルに書き出し、正常完了後に上書きする方式を採用し破損を防ぐ。
- **UI分離**: ロジック層はヘッドレスとし、GUIを差し替えるだけでコンソール版/ブラウザ版に対応させる。
