# 01_システム設計書

## 1. 画面状態遷移
- `Idle`: 初期状態。
- `Playing`: 合成処理中。
- `Success`: 成功演出中。
- `Failure`: 失敗演出中。失敗時の組み合わせは履歴として内部保持する。
- `Result`: 合成結果表示。合成成功/失敗のフィードバックを表示する。
- `Menu`: 設定・図鑑表示。

## 2. データフロー
- フロントエンド状態管理: React Context によるグローバル状態管理。
- データ同期: ローカルキャッシュ最適化型を採用。頻繁に更新される精霊/成長ステータスはフロントで即時反映し、サーバーと非同期で同期する。

## 3. コンポーネント階層
- `App` (Root)
  - `GameLayout` (全体枠組み)
    - `Header` (Status/Title)
    - `SpiritPanel` (成長要素表示エリア: 精霊/ホムンクルス)
    - `Main` (Mixer/Inventory)
    - `Footer` (Navigation)
  - `Overlay` (演出用レイヤー)
  - `Modal` (Details/Settings)

## 4. システム制御方針
- **エラーハンドリング**: 通信失敗時は、ユーザーに「再試行」を促すトースト通知を表示し、UI状態を `Idle` へ戻す。
- **永続化**: 精霊のレベルや入手素材は LocalStorage にキャッシュし、ブラウザリロード時にも前回プレイ状態を維持する。
- **データ整合性**: サーバーのレスポンスを正とする。Optimistic UI で反映後、サーバーからの応答で不整合があった場合は、サーバーの状態に強制的に上書き（Reconciliation）する。
